The path, stage by stage

STAGE 1

Ingest

  • Scheduled extracts from the EHR reporting layer, FHIR APIs, and departmental flat files
  • Load checks on row counts and freshness, so a missed load pages someone before a dashboard goes stale
SQLFHIRSFTP

Done it: integrate six source systems into a SQL Server warehouse for DoD's Defense Acquisition University, with alerting on failed and missed loads.

STAGE 2

Transform

  • dbt models with tests on keys, nulls, and accepted values
  • Lineage from raw table to model feature, so any number can be traced back to its source
dbtETL/ELTlineage

Done it: 50+ Informatica mappings serving 100,000+ users; root-cause analysis through source-to-target lineage.

STAGE 3

Train and track

  • Every run logged in MLflow: data version, parameters, metrics, artifacts
  • Models registered with owners and a model card that data scientists and clinicians can both read
PythonMLflowscikit-learn

Done it: scikit-learn and PyTorch models on AWS SageMaker, 30% accuracy gain on client work.

STAGE 4 · GATE

Validate before anything ships

  • Performance and calibration reported per age band, never only overall
  • Subgroup checks for fairness across patient populations
  • Clinical owner signs off in the registry before promotion
calibrationsubgroupssign-off

Done it: built evaluation pipelines that keep LLM answers grounded in source documents.

STAGE 5

Deploy

  • Batch scores written back to the warehouse for dashboards, or a containerized API for real-time use
  • CI/CD with code review, so a change is tested and reversible
DockerCI/CDGit

Done it: CI/CD for a DoD data warehouse, 35% faster delivery and 50% fewer deployment errors.

STAGE 6

Monitor

  • Input drift, output drift, and outcome-based performance once labels arrive
  • An alert sends a model back to stage 3 for retraining, not silently degrading
driftalertingretraining

Done it: replaced ticket-driven failure discovery with proactive monitoring on production pipelines.

Stage 6 feeds back into stage 3. The loop is the product.

Why pediatrics changes the checklist

A model that looks accurate overall can be wrong for the youngest patients, because normal ranges move with age and some groups are small. So the validation gate reports results in age bands like these, with the sample size next to every number.

Age bandTypical resting heart rateWhat the gate checks
Neonate (0 to 28 days)100 - 205 bpmSmall cohort, so wide confidence intervals are shown, not hidden
Infant (1 to 12 months)100 - 180 bpmFeatures that depend on weight are scaled, not raw
Child (1 to 10 years)60 - 140 bpmCalibration per band, so a 20% risk means 20%
Adolescent (11 to 17 years)60 - 100 bpmAdult-like ranges, compared against adult-trained baselines

Heart rate ranges are approximate published pediatric reference values, shown to illustrate why a single threshold fails across ages.
